## 上午：替身方案实现（单卡版 ✅）

放弃在 Card.tsx 上直接改造的路线（v1 三次失败），改用**替身方案**：

1. 拖拽时不动原卡，在 `document.body` 上 Portal 渲染分身
2. 分身内部复用 `<Card location="bench" />` 获得 1:1 外观
3. Portal 割断 DOM 嵌套 → 彻底规避 motion.div transform 竞态
4. `useMotionValue → useVelocity → useTransform → useSpring` 伪3D物理倾斜

### 核心文件

| 文件 | 作用 |
|------|------|
| 🆕 `DragGhostCard.tsx` | 替身组件 — Portal + 伪3D物理倾斜 |
| ✏️ `Battlefield.tsx` | 战场格子加 `data-drop-zone` / `data-combat-index` |
| ✏️ `GameSession.tsx` | 拖拽状态 + 事件委托 + 落点判定 + `toggleAttacker`/`assignBlocker` |

### 关键技术细节
- **防误触**：8px 阈值，低于=点击，高于=拖拽
- **原卡隐藏**：直接 DOM 操作 `style.pointerEvents='none'` + `opacity='0'`
- **恢复延时**：`setTimeout(0)` 避开 click 冒泡
- **落点判定**：`document.elementsFromPoint()` + `closest('[data-drop-zone]')`
- **分阶段行为**：`main/attack_declare` → `toggleAttacker`；`block_declare` → `assignBlocker`
- **事件委托**：利用 Card 已有的 `data-entity-id`，不修改 Card.tsx

## 下午测试：程的反馈

### 成功 ✅
- **终于拿起了备战席的卡牌！** 替身方案核心验证通过
- 缩放参数已暴露为 `GHOST_CARD_SCALE`（程调到了 1.5）

### 问题 1：红色 🚫 禁止图标
- **症状**：只能在卡牌上半部分（战力/血量数值区）拖拽，下半部分（卡面图片区域）拿起瞬间被拦截
- **推测根因**：浏览器对 `<img>` 的原生拖拽劫持了 pointer events
- **状态**：待修复 ❌

### 问题 2：拖拽不上战场
- **症状**：无论主阶段还是进攻宣告阶段，拖到战场后卡牌不上去
- **推测根因**：可能是问题1的连锁反应（事件被劫持后 `toggleAttacker` 没执行），也可能是 `findDropZone` 找不到落点
- **状态**：待修复 ❌

### 尝试：多卡队列功能
- 实现了扫过备战席自动收集多张卡牌 + 错位排列 + 一次性全部 `toggleAttacker`
- 但合并问题1/2修复后 → **拖拽完全失效**，程要求彻底回滚
- **状态**：已回滚，代码不留痕迹 ❌
